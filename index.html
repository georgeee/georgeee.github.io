WHAT I'M THINKING ABOUT

Engineering when the code is generated

AI has made implementation dramatically faster. It also makes it easy to produce plausible code without understanding every failure mode.

I've therefore been moving more of my attention to what surrounds the implementation: writing down the properties that matter, isolating components so that mistakes stay local, and using checks that are independent of whoever produced the code — and that fail differently from one another, so a disagreement shows up rather than being averaged away.

A lot of my recent work, including agent-cage, was built this way.

Formal methods at AI speed

Formal verification has always had an economics problem: for most software, writing and maintaining proofs costs too much.

I think agents may change that. I've been using them to help construct proofs and iterate on formal specifications, while the trusted checker remains small and deterministic.

Molt Petit is my first substantial experiment in this direction. The thesis, at Yak →

The AI insider

Companies are about to run AI agents inside their own infrastructure: wide access, machine speed, and motives that are not fully legible and can be altered from outside. We learned, more or less, how to hire people without fearing them. With AI insiders that is still open.

The question I'm working on: how do you keep a company's most important records correct, and private, when something inside — with access to every server — may be wrong or turned?
